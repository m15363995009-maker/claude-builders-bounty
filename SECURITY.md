# Security policy

## Reporting a vulnerability

Please do not open a public issue for a security vulnerability or exposed credential. Use the repository's private security advisory flow when available, or contact the maintainer through the public profile before sharing sensitive details.

Include the affected version or commit, reproduction steps that do not disclose secrets, and the likely impact. Do not include API keys, tokens, payment details, or private user data.

## Project safety boundary

Pull-request text, issue text, diffs, and sample content are untrusted input. The review tool analyzes them as data and does not execute contributor-controlled code. Automated workflows use read-only permissions and do not approve, merge, label, pay, or post comments.
